# ADR-007: Observability: structured logs, Prometheus metrics, OpenTelemetry traces, and an append-only timeline

- Status: Accepted, implemented (2026-09-10)
- Code: `src/aegis/logging.py`, `src/aegis/telemetry/metrics.py`, `src/aegis/telemetry/tracing.py`,
  `src/aegis/api/middleware.py`, `docker-compose.yml` (`observability` profile),
  `infrastructure/{prometheus,grafana,otel,tempo,loki,promtail}`, `scripts/gen_dashboards.py`

## Context

"The observability layer records" is part of the identity statement. Operators need to answer: what
did the agent do, why was a tool refused, how long did approval take, is the LLM healthy, is the
detector the leader. Secrets must never reach logs.

## Decision

- **Logs**: structlog, JSON by default (`AEGIS_LOG_FORMAT=console` for humans), with
  `redact_processor` masking secret-looking keys (`api_key`, `authorization`, `password`, `token`,
  ...) and values (`sk-…` or `Bearer …` followed by at least eight further characters), and
  contextvars binding `request_id`, `incident_id`, `workflow_id`, `agent_run_id` so a grep on one id
  follows a request through API, activities and the agent. Noisy third-party loggers are capped at
  WARNING.
- **Metrics**: one `CollectorRegistry` with `aegis_*` counters, gauges and histograms:
  `aegis_incidents_total{severity,flow}`, `aegis_incidents_active`,
  `aegis_incident_resolution_seconds{outcome}`, `aegis_agent_runs_total{phase,termination}`,
  `aegis_agent_iterations{phase}`, `aegis_tool_calls_total{tool,status}`,
  `aegis_tool_failures_total{tool}`, `aegis_tool_latency_seconds{tool}`,
  `aegis_policy_denials_total{code,tool}`, `aegis_approval_wait_seconds`,
  `aegis_approvals_total{decision}`, `aegis_remediation_total{tool,status}`,
  `aegis_rollback_total{status}`, `aegis_verification_total{status}`,
  `aegis_llm_calls_total{model,schema,outcome}`, `aegis_llm_tokens_total{model,kind}`,
  `aegis_llm_latency_seconds{model}`, `aegis_detection_signals_total{kind}`,
  `aegis_detection_cycle_seconds`, `aegis_http_requests_total{method,route,status}`,
  `aegis_http_request_seconds{method,route}`; the `_seconds` ones are histograms, so the scrapeable
  series are `_bucket`/`_sum`/`_count`. Exposed at API `/metrics` (which also refreshes
  `aegis_incidents_active`), worker `:9464`, detector `:9465`. `AEGIS_METRICS_PORT` is not a
  `Settings` field — `config.py` sets `extra="ignore"`, which would drop it — so the worker and
  detector read it with raw `os.environ.get` (defaults `9464` and `9465`), and setting it once in a
  shared env block collides for both processes. `start_http_server` is wrapped in
  `contextlib.suppress(OSError)`, so a port collision silently leaves the process with no metrics
  endpoint; the custom registry means no default `python_*`/`process_*` collectors are exposed; and
  the `metrics_enabled` setting is declared in config but never read. The simulator exports its world
  as `sim_service_*`/`sim_infra_*` plus `sim_active_faults` and `sim_tick_count` at `:8601/metrics`.
- **Traces**: OpenTelemetry is off by default and switched on with `AEGIS_OTEL_ENABLED=true`
  (OTLP gRPC to `AEGIS_OTEL_EXPORTER_ENDPOINT`). When on: SQLAlchemy and httpx auto-
  instrumentation, Temporal's `TracingInterceptor`, and manual spans `aegis.tool.execute`
  (`aegis.tool`, `aegis.category`, `aegis.incident_id`, `aegis.status`, `aegis.attempts`) and
  `aegis.llm.complete` (`aegis.model`, `aegis.schema`, `aegis.input_tokens`, `aegis.output_tokens` —
  there is no single `tokens` attribute). FastAPI auto-instrumentation never actually activates in
  the API process: `instrument_fastapi(app)` runs while the app is constructed and returns early
  because tracing is not configured yet — `configure_tracing` only runs later, inside the lifespan's
  `build_runtime`.
- **Product-level record**: every meaningful step is an `IncidentEvent` in the `incident_events`
  table (per-incident `seq`), which is append-only by application convention — the database-level
  immutability trigger exists on `audit_events` alone. Events are fanned out over Redis pub/sub and
  served as SSE, and only the per-incident stream replays: `/api/v1/incidents/{id}/stream` honours
  `after_seq`/`Last-Event-ID` and replays up to 2000 rows, while `/api/v1/events/stream` is a live
  firehose with no replay. Security-relevant decisions are also `audit_events`, immutable at the
  database.
- **Local stack**: `docker compose --profile observability up` adds Prometheus (jobs `aegis-api`,
  `aegis-worker`, `aegis-detector`, `simulated-infrastructure` and `otel-collector` on `:8889`),
  Grafana with two provisioned dashboards ("Aegis — Runtime Overview", "Aegis — Simulated
  Infrastructure"; JSON generated by `scripts/gen_dashboards.py`), Tempo, Loki + Promtail (container
  logs, filtered on the compose project name `aegis`) and an OTel collector.

## Consequences

- No metric is defined without a call site; the list above is exactly what
  `src/aegis/telemetry/metrics.py` declares and the code increments.
- The timeline is the primary debugging tool and is complete without any external stack; Prometheus
  and Tempo are optional depth.
- Logs never carry the OpenAI key or API keys; the redaction is tested
  (`tests/security/test_tool_abuse.py::test_secrets_never_reach_logs`).
- Tracing adds an exporter dependency and a collector in production; the toggle keeps the spine
  free of it when unwanted.

## Alternatives considered

- Logs only: cannot answer rate/latency questions or drive dashboards.
- A vendor SDK: locks the runtime to one backend; OTel keeps the exporter swappable.
- Metrics from the API process only: the worker and detector run the interesting code paths and
  must export their own.
